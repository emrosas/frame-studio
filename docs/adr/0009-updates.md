# 0009: The unsigned app updates itself from GitHub Releases

Status: accepted, 2026-09-26. Amends ADR 0008, which left updates for later.

## Context

Users install Frame Studio from a DMG on GitHub Releases. They should get new versions the way T3 Code users do. The app notices a newer version and offers Update, and one click downloads it, checks it, replaces the app and restarts it. T3 Code does this with electron-updater, which on macOS hands the install to Squirrel.Mac. Squirrel.Mac refuses any update unless the running app and the update are both signed with the same Developer ID. Frame Studio has no Apple Developer ID yet and ships unsigned (ADR 0008), so electron-updater can't install anything for it.

## Decision

- **Our own updater until the app is signed.** It lives in `desktop/updater.ts`, in the main process, with the steps that need no Electron in `desktop/update-steps.ts`. It adds no dependency.
- **electron-updater's feed.** A release is a GitHub release tagged `v<version>` with three files: `Frame-Studio-<version>-arm64-mac.zip`, `Frame-Studio-<version>-arm64.dmg` and `latest-mac.yml`. The feed is in electron-builder's format and gives the version, the zip's URL, base64 SHA-512 and size, and the release date. The app reads `releases/latest/download/latest-mac.yml`, which GitHub redirects to the newest release that is neither a draft nor a prerelease, and resolves the zip's URL against it. A small parser reads that one shape, so there is no YAML library. `FRAME_STUDIO_UPDATE_FEED` points the app at another feed, for tests.
- **When it checks.** Only the installed app checks, or an app given a test feed, and never the render worker. It checks 10 s after launch, then every 4 hours, and when the user picks Check for Updates… in the app menu. Versions compare as semver, so a prerelease comes before its release. A background check that fails only writes to the log. A check the user asked for says what it found or why it failed.
- **The pages get the state.** Main pushes an `UpdateState` to the viewer and the welcome page: idle, checking, available, downloading, restarting or error. Their preloads expose `updates` only when the app can update, and main answers those calls only from the app's own pages. The viewer's UI for it is separate work.
- **One click.** Update downloads the zip into a temporary folder, with progress, and checks its size and SHA-512 against the feed. `ditto` unpacks it into a hidden folder beside the app, so the swap is a rename on one volume. The result must be one `Frame Studio.app` with the running app's bundle id and the feed's version. The app strips the quarantine attribute from it, starts a detached shell script, and quits. The script waits for the app's process to end, moves the old bundle aside, moves the new one into its place and deletes the old one. If a move fails it puts the old bundle back. Then it opens the app again with `open -n`, and passes on any `FRAME_STUDIO_*` variables with `open --env`, which tests need to keep their temporary settings. It logs to `update.log` beside the app's other logs. Anything that fails before the quit leaves the installed app as it was.
- **Where it can't.** An app that macOS runs translocated, or that runs from the mounted DMG, another read-only volume or a folder the user can't write to, can't replace itself. Update says so and the error carries `manual: true`, so the UI offers the release page instead.
- **Releases.** `npm run desktop:release` refuses to build unless the tag is new, HEAD is on origin/main and the files that ship have no uncommitted changes. It builds the zip beside the DMG, checks that the zip unpacks to an app of the right version with its framework symlinks, and writes `latest-mac.yml`. With `--publish` it creates the GitHub release with `gh`. `docs/RELEASING.md` has the steps.

## Consequences

- The app has to live in a folder the user can write to, such as /Applications for an admin account. Run from the DMG, or from Downloads before it was moved, it asks to be moved first.
- The first install has no Developer ID. The build signs the app ad hoc, a valid signature with no identity, so Gatekeeper says it can't verify the downloaded app and the user allows it once with Open Anyway in System Settings › Privacy & Security. Before the ad hoc signature, only Electron's main binary carried a signature, which didn't verify over the bundle, and macOS called a downloaded copy damaged with no way to open it but Terminal. Updates don't meet Gatekeeper, since the app downloads them itself and strips the quarantine attribute.
- Nothing proves who built an update beyond HTTPS to GitHub and a checksum published on the same release. Anyone who can publish a release on the repo can ship code to every installed app. Signing closes that gap.
- Every update downloads the whole app, about 124 MB. electron-builder writes blockmaps for differential downloads, which electron-updater can use after the switch.
- **When there is a Developer ID.** Sign and notarize in `tools/desktop/package.ts` (the identity, the hardened runtime and notarization), and replace `desktop/updater.ts` with electron-updater and its GitHub provider. The tags, file names and feed stay the same, so releases made before the switch still work. The last unsigned version's updater installs the first signed one, since it checks only the bundle id, the version and the checksum. Keep pushing the same `UpdateState`, and the viewer's UI needs no change. Squirrel.Mac then does the swap, with its own rules about where the app may run.
